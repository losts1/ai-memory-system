================================================================================
TITLE
================================================================================

BUG: MemoryStateManager constructor expects session_id, not agent_id
API: Multi-agent parameter naming inconsistency

================================================================================
SEVERITY
================================================================================

HIGH - Breaking API change affecting multi-agent implementations

================================================================================
ISSUE DESCRIPTION
================================================================================

The MemoryStateManager class has a parameter naming mismatch that breaks code
expecting agent_id= parameter. The class uses session_id= instead, while other
multi-agent APIs in the same library use assistant= parameter.

================================================================================
CURRENT BEHAVIOR
================================================================================

from ai_memory import state

# Expected usage (based on multi-agent patterns elsewhere):
manager = state.MemoryStateManager(agent_id="test-agent")

# Actual error:
# TypeError: __init__() got an unexpected keyword argument 'agent_id'

# Current correct usage:
manager = state.MemoryStateManager(session_id="session-1")

================================================================================
EXPECTED BEHAVIOR
================================================================================

The API should either:
1. Accept agent_id= parameter (for clarity in multi-agent contexts)
2. Or use consistent parameter naming across all multi-agent APIs

================================================================================
CURRENT SIGNATURE
================================================================================

Location: ai_memory/state.py

class MemoryStateManager:
    def __init__(self, workspace=None, session_id: Optional[str] = None):
        ...

================================================================================
API INCONSISTENCY EVIDENCE
================================================================================

Other modules use assistant= for agent scoping:

  graph.traverse(..., assistant="Claude")
  search.search_files(..., assistant="Claude")
  learn.sync_facts(..., assistant="Claude")

But MemoryStateManager uses:

  state.MemoryStateManager(session_id="session-1")

This creates naming inconsistency for developers building multi-agent systems.

================================================================================
ROOT CAUSE ANALYSIS
================================================================================

This appears to be a Phase 2/Phase 3 refactoring artifact where:

1. Multi-agent support was added with assistant= parameter (Phase 2)
2. MemoryStateManager was extracted to library (Phase 3)
3. Parameter naming was not standardized across new modules
4. session_id= was used instead of agent_id= or assistant=

The parameter name session_id suggests single-session context, but the class
is intended for multi-agent scenarios (based on usage in graph/search/learn APIs).

================================================================================
PROPOSED SOLUTIONS
================================================================================

SOLUTION 1: Add agent_id= Parameter (RECOMMENDED - Backwards Compatible)
----------------------------------------------------------------------

def __init__(self, workspace=None, session_id: Optional[str] = None,
             agent_id: Optional[str] = None):
    # Accept both, prefer agent_id if provided
    final_id = agent_id or session_id
    self.session_id = final_id

Pros:
  - Backwards compatible
  - Clear intent (agent_id is clearer than session_id for multi-agent)
  - Allows future migration to assistant= if desired

Cons:
  - Two parameter names for same concept (temporary)


SOLUTION 2: Rename to agent_id= (BREAKING CHANGE)
--------------------------------------------------

def __init__(self, workspace=None, agent_id: Optional[str] = None):
    self.agent_id = agent_id
    self.session_id = agent_id  # Alias for compatibility

Pros:
  - Consistent with multi-agent patterns
  - Clearer naming

Cons:
  - Breaking change
  - Requires migration guide
  - Version bump needed


SOLUTION 3: Standardize on assistant= (DESIGN ALIGNMENT)
-------------------------------------------------------

Rename across all modules:
  - state.MemoryStateManager(assistant=...)
  - (already using in graph/search/learn)

Pros:
  - Single consistent parameter name across library

Cons:
  - Breaking change to all modules
  - Requires major version bump
  - Largest migration effort

================================================================================
RECOMMENDATION
================================================================================

SOLUTION 1 (Add agent_id= parameter)

Timeline:
  - v1.3.3: Add agent_id= parameter, deprecate session_id=
  - v1.4.0: Decide on final parameter name
  - Update CHANGELOG and migration docs
  - Update all examples and tests

This maintains backwards compatibility while fixing the API inconsistency.
